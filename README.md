# CS-305-12299-M01-Software-Security
Artemis Financial is a financial services company that needed help locking down their existing Spring Boot web application. The main goals were verifying data integrity, encrypting client-server communication, and scanning their dependencies for known security flaws. One thing I think I did really well was using the OWASP Dependency-Check tool to dig into their third-party libraries, the scan turned up 13 vulnerable dependencies and 160 CVEs, which was a pretty eye-opening reminder that clean-looking code can still be a liability if the dependencies aren't secure. Coding securely matters because one exploited vulnerability can expose sensitive customer data, ruin a company's reputation, and come with serious legal and financial consequences. For a financial company like Artemis, security cant be optional. The most challenging part of the vulnerability assessment was honestly just the volume of flagged issues in the dependency report; it took judgment to figure out which CVEs were actually applicable versus which ones could be safely suppressed. To increase layers of security, I implemented HTTPS/TLS for encrypted communication, SHA-256 for checksum verification, and OWASP Dependency-Check for catching vulnerable libraries, multiple overlapping protections. 

After refactoring the code, I ran the application to confirm that the HTTPS endpoint and SHA-256 checksum were both working correctly, then re-ran the dependency scan to make sure I didn't introduce any new vulnerabilities. Comparing the before-and-after reports was a really useful way to verify that my changes didn't make things worse. The tools and practices I'd bring into future projects include the OWASP Dependency-Check Maven plugin, Java Keytool for SSL/TLS certificate generation, Spring Boot's SSL configuration, and NIST's published hashing standards like FIPS 180-4. I'd want to show a future employer because it's a full end-to-end example of identifying real vulnerabilities, implementing actual fixes, following NIST and OWASP standards, and documenting the whole process clearly.
